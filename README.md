# Flamingo

> Проект [WHITE OBSERVATORY](https://whiteobservatory.com).

Платформа живых онлайн-уроков. Преподаватель заводит урок и зовёт учеников ссылкой или приглашением;
класс встречается в комнате с видео, звуком, доской, материалами и чатом; после урока остаются
кабинет, журнал и переписка. В платформу встроен модуль аналитики вовлечённости **SEduM**.

| | |
|---|---|
| Сайт | https://flamingo.plus — фронт, Cloudflare Pages из ветки `v1` |
| API | https://api.flamingo.plus — Django, свой сервер |
| Источники мира | https://hub.flamingo.plus — посредник `hub-proxy/` для сайтов, запрещающих показ в рамке |
| SEduM | https://flamingo.plus/sedum/ — витрина модуля и научный кабинет |
| Медиа | LiveKit Cloud (Франкфурт) · почта — Resend |
| Состояние | 19.11.2026, коммит «Georgian: Noto Sans Georgian font…» |

Порядок работы над проектом — `ПРАВИЛА-РАБОТЫ.md`. Что такое Flamingo v1 целиком и в каком порядке
он собирается — `docs/FLAMINGO-V1.md`. Карта кода — `docs/АУДИТ-2026-10/00-ОБЩЕЕ.md` §1.

## Что работает

Проверено по коду и прогонам на 22.11.2026.

| Область | Где в коде |
|---|---|
| Учётные записи: регистрация, вход, восстановление пароля, сессия на 30 дней | `backend/people/` |
| Админка владельца: люди, проверка преподавателей, блокировка, журнал действий | `backend/people/urls_admin.py`, `frontend/src/screens/Админ.tsx` |
| Уроки, материалы, журнал, приглашения, визиты, список преподавателей, переписка | `backend/study/` |
| Комната урока: плитки и сцена, показ документов, ролики под управлением учителя, чат, полка источников, рукописные пометки | `frontend/src/room/`, `backend/room/` (пропуск в LiveKit) |
| Доска: холст, объекты, листы, отмена и возврат | `frontend/src/board/` |
| «Источники мира»: каталог музеев и источников, превью, избранное, показ через посредника | `backend/common/`, `frontend/src/hub/`, `hub-proxy/` |
| SEduM CMF в уроке: внимание по камере считается на устройстве, балл видит только ведущий | `frontend/src/sedum/`, `frontend/src/room/внимание.ts` |
| Исследование внимания с добровольцами: согласие, анкета, запись, кабинет владельца, выгрузка, удаление | `backend/science/`, `frontend/src/наука/` |
| Интерфейс на 7 языках: русский, английский, грузинский, французский, испанский, немецкий, турецкий; арабский подготовлен и скрыт | `frontend/src/lib/язык.ts`, `frontend/src/lang/` |

Пока не сделано: роль родителя, школы, платные курсы, домашние задания отдельным модулем.

### SEduM

SEduM (Supporting, Education, Monitoring) — система модулей вокруг урока. Решения владельца — `docs/SEduM.md`.

| Модуль | Состояние |
|---|---|
| CMF — Concentration Monitoring & Feedback | работает в уроке; сырые кадры не покидают устройство |
| Flamingo Test & RND | исследование внимания с добровольцами (`/наука/…`) |
| BioProfile, Bioimef | описаны на витрине `/sedum/`, в коде пока нет |
| AI Teacher (команда IRIS) | проектируемое направление, только витрина |

Модуль `science` хранит на сервере записи добровольцев с их согласия — это отдельно от урока,
где кадры остаются на устройстве. Тексты согласия и публичные формулировки нужно держать в
соответствии с этим различием.

### ROOM

Комната урока — сердце продукта: Django-приложение `backend/room` выдаёт пропуск в LiveKit по коду
комнаты, а вся комната живёт во фронте (`frontend/src/room/`, около 40 файлов, экран `screens/Room.tsx`).
С 28.08.2026 проект начался именно с неё («комната по ссылке на двоих»), остальное наращивалось вокруг.

## Запуск

Порты закреплены за проектом: **фронт 5180, бэкенд 8080**. `--strictPort` не даёт фронту тихо
уехать на соседний порт.

```bash
cd backend
python3 -m venv .venv && ./.venv/bin/pip install -r requirements.txt   # один раз
./.venv/bin/python manage.py runserver 8080
```

```bash
cd frontend
npm ci        # один раз
npm run dev   # http://localhost:5180
```

Проверка, что бэкенд жив: `curl http://localhost:8080/api/room/healthz` → `{"ok": true, "livekit": true}`.
Переменные окружения — `backend/.env.example`, `frontend/.env.example`.

## Проверки

```bash
cd frontend && npm run check    # типы, ~25 приборов с самопроверкой, сборка
```

Бэкенд проверяется скриптами-прогонами, а не `manage.py test`:

```bash
cd backend
for f in room/прогон.py people/прогон.py people/прогон_админки.py study/прогон.py \
         science/прогон.py common/прогон.py common/прогон_избранного.py; do
  ./.venv/bin/python "$f" || break
done
```

`hub-proxy`: `cd hub-proxy && npm ci && npm test`.

Приборы не заменяют живого прохода: кусок не сдан, пока путь не пройден вживую двумя окнами.

## Выкат

- Фронт: `git push origin main:v1` — Cloudflare Pages собирает ветку `v1`.
- Бэкенд и `hub-proxy` выкатываются на сервер отдельно — `docs/ОБНОВИТЬ-СЕРВЕР.md`, `docs/ВЫКАТ.md`.
